### 三、剪輯師任務頁改版（PR #12，已上線）

#### 1. 電腦版版面（手機版完全不動）
- 螢幕 1024px 以上改成兩欄：
  - **左欄**：任務清單，一支一橫列，依序是「交片期限｜IP＋片名＋備註＋聯繫窗口｜交片送審按鈕」。預設先攤開 12 筆，手機是 8 筆。
  - **右欄**：捲動時固定在畫面上。由上到下是三個數字（要剪／剪好待傳／本月已上傳）、「剪好了，還沒傳雲端」、灰字「對帳用」兩區（已交片等安排上片、已經排好了）。
- 「還沒排到上片日」接在左欄清單最後面。
- 字級：日期、IP、剪輯備註、素材連結從 13px 改成 15px；按鈕下的說明小字在電腦版拿掉。
- 寫法：電腦版樣式一律用 Tailwind 的 `lg:` 前綴，沒有前綴的 class 都是手機版的，不要動。

#### 2. 剪輯師只看「交片期限」，不看上片日
- **交片期限＝上片日往前推 7 個工作天**（跳過週六、日；國定假日沒有排除）。例：10/10 上片 → 10/01（四）前交片。
- 為什麼：原本寫「10/10 要上、剩 7 天」，剪輯師照上片日剪一定來不及。公司規定交片後要留 7 個工作天走完審稿到上傳雲端。
- 倒數顯示規則：

  | 狀況 | 顯示 | 顏色 |
  |---|---|---|
  | 還有 4 天以上 | 剩 N 天 | 灰 |
  | 剩 1～3 天 | 剩 N 天 | 橘 |
  | 期限就是今天 | 今天 | 橘 |
  | 毛片建檔時期限就已經過了 | 盡快 | 橘 |
  | 已經超過期限 | 已超過 N 天 | 紅 |
  | 「沒片」那一列過了期限 | 盡快 | 橘（不標紅，剪輯師手上沒料可剪） |

- 主清單照交片期限排，**急件永遠排最前面**。
- 「我的所有片」卡片上原本的「MM/dd 要上」，也改成交片期限。只在待剪、業主要改兩關顯示。
- 程式在 `src/lib/editorQueue.ts`：`EDIT_LEAD_WORKDAYS`、`deliveryDeadline`、`customDeadline`、`deadlineStatus`、`formatDeadline`。

#### 3. 急件顯示
- 急件一律只顯示橘色火焰「🔥 急件」（用 lucide 的 `Flame` 圖示，不是 emoji），不顯示推算出來的期限。
- 清單那一列的卡片上，不再重複紅色「急件」標籤。
- 例外：同事親手指定過交片日的急件，下面會多一行小字「MM/dd 前交片・同事指定」。

#### 4. 同事指定「預計交片日」
- 位置：素材資料庫 → 待剪素材卡 →「急件」旁邊的「交片日」按鈕。點了會跳出日曆；設定後顯示「10/05 交片 ×」，按 × 清除。
- 欄位：`asset.editDueDate`（YYYY-MM-DD）。
- 效果：剪輯師清單上那支片的期限改成這個日子、標「同事指定」，清單排序跟著變。沒配到上片日、但有指定交片日的毛片，也會進主清單。
- ⚠️ **交片日刻意不參與「哪支毛片／成片配哪一天」的配對。** 配對規則（`materialSupply.queueOrder`、`editorQueue.rawOrder`）同時被排片建議、上片排程表、剪輯師的上片排程頁使用。交片日在片交出去之後還留在資料上，加進配對會改到小編的排片建議。

#### 5. 素材聯繫窗口
- 新建的素材會記下建檔人名字，欄位是 `asset.createdByName`。剪輯師讀不到員工資料，所以要另外存一份。
- 會寫入這個欄位的地方有三處：素材資料庫手動建檔、整批上傳毛片、從雲端認領。
- 剪輯師卡片顯示「素材聯繫窗口：XXX」。素材資料庫卡片底部原本那個沒標名稱的建檔日，也改成這一行。
- 舊素材不補，沒有名字就整行不顯示。

#### 6. 審查時修掉的問題
- **任務頁數字被篩掉**（本來就有的問題）：「我的剪輯任務」和「我的所有片」共用同一份畫面狀態。在「我的所有片」點了 IP 或「只看急件」再切回來，任務頁的「要剪／剪好待傳」和待上傳區會被篩掉，看起來像片不見了。修法是任務頁改用不篩選的清單 `queueToEdit` / `queueToUpload`。
- **交片日影響排片建議**：見第 4 點的 ⚠️，已改成不參與配對。

#### 7. 權限規則
- 不用改 `firestore.rules`：`isValidAsset` 不會拒絕新的選填欄位。剪輯師的可寫欄位白名單裡沒有 `editDueDate` 和 `createdByName`，所以剪輯師改不了。
